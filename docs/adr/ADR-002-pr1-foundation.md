# ADR-002：PR1 基础设施和契约补充决定

- 状态：已接受（2026-11-13 合入 main）
- 日期：2026-11-09
- 补充：[ADR-001](ADR-001-v1-architecture.md)

## 数据持久性

**背景**：批量文件发布、冲突和进程中断均不能静默丢失接收证据。

**决定**：在 `DATA_ROOT/recovery/` 保存冲突文件和遗留 partial，并记录说明；单机协作写入及扫描通过锁文件协调；锁被占用时立即失败、不等待，数据不变，由调用方决定是否重试。初始化持锁时扫描全部六层并重算 recovery 文件校验和，数据增大后耗时增加；带超时等待和缩小扫描范围留待 PR2（负责人决定，2026-11-13）。写入文件和发布后的父目录均执行同步，写入前检查文件系统是否支持硬链接；macOS 的 `/Volumes/<卷名>` 必须是非软链接的实际挂载点。Bronze 路径包含接收身份，只有同一次写入的重复尝试可以把相同字节视作成功。

**理由与后果**：不覆盖发布和单独保存失败内容有利于追溯；恢复区需人工处理，文件系统及硬件的持久性能力仍需在实际环境验证。未来 WebSocket 录制采用分段追加日志，定期同步并在中断后逐条校验恢复；批量 writer 不等于实时录制器。

## 数据契约

**背景**：字段说明和规则分散时容易与代码不一致。

**决定**：`src/data_schema/` 下的 JSON 声明 schema、字段说明和行级规则，`docs/SCHEMAS.md` 的字段表由脚本生成。每条记录可独立判断的硬规则在 contract；跨行和跨文件验证留待 PR4。UTC 时间必须使用 `datetime.timezone.utc`。字段或规则变化均升级契约版本，不兼容变更升级主版本。

**理由与后果**：统一声明便于核查和版本化，但 JSON 规则执行器和 registry 自检必须一起维护；契约通过不代表数据集覆盖完整或跨行一致。

## Point-in-time

**背景**：事件发生时间与信息可用时间并不一定相同。

**决定**：第一层 contract 检查 feature 的可用时间不晚于观察时间；第二层在未来训练集构建和回测中检查可用时间不晚于决策时间减去信息延迟。延迟默认一分钟，放在实验配置并记录；缺失的历史可用时间只能使用经批准且记录的假设。

**理由与后果**：避免将事后信息带入回测。当前 contract 不替代未来的第二层检查。

## 配置

**背景**：字段合法性需要可复用的定义，任务参数与机器环境需要分开。

**决定**：模型以 pydantic 声明并验证配置；只有 `PipelineConfig` 接受环境变量覆盖，`.env` 保存敏感信息和机器级全局设置。未来特征数据参数放在 `src/config/profiles/features/`，随运行和 manifest 记录；参数变化产生新的 `data_version`。

**理由与后果**：可以复用严格校验并保留运行可追溯性；特征 profile、manifest 和相关任务在实际调用方出现时实现，PR1 不预建空模块。

## Adapter 与日志

**背景**：规范化失败必须保留证据并可与程序错误和不支持能力区分。

**决定**：规范化错误统一携带数据集、原因和原始记录，溯源字段从 Bronze 外壳取得，并提供全部 Silver 数据集对应的规范化接口。来源没有或不适用 API/协议版本时，adapter 声明为 `None`，不编造（负责人决定，2026-11-13）；Bronze 记录按 `(venue, api_version, protocol_version)` 精确相等路由到 adapter，路由在外壳契约校验和解析原始内容之前检查（只在三项身份字段形式合法时比较，形式不合法按外壳契约错误处理）。规范化输入可以是普通 `dict`，或底层确认为普通 `dict` 的只读映射代理（负责人决定，2026-11-13；底层确认依赖 CPython 的 `gc.get_referents`，其他 Python 实现上合法代理会安全退回原引用路径、无法规范化）；其他映射不复制、保留原引用并标为非快照。证据先复制再路由，因此无法复制的误路由外壳报规范化错误。adapter 不再单独声明 validation rules，校验规则统一来自 `src/data_schema/` 的共享契约（负责人决定，2026-11-13，补充 ADR-001 第 5 条）。CLI 命令的 `pipeline_logging` 上下文为 `src` logger 输出每行一个 JSON 对象，包含 UTC 时间、级别、事件名和消息；有运行标识时附带 `run_id`，不记录密钥。普通 CLI 输出和上下文之外的库调用不自动变成 JSON 日志。

**理由与后果**：调度器可按错误类别处理 quarantine 并关联运行；真实 venue、持久化 quarantine 和运行账本仍属于后续 PR。
