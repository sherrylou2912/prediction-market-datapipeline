# PR1 工作拆分计划

本计划记录负责人已讨论并认可的 PR1 分块。基础设计见 [`docs/pr1/FOUNDATION_RULES.md`](FOUNDATION_RULES.md)，项目权威规则见 [`agent/PROJECT.md`](../../agent/PROJECT.md)。计划不等于实现；具体代码、测试和状态以工作区及每块报告为准。

## 目标与边界

PR1 建立配置、数据定义与结构、质量和审计、运行与实验记录等基础约定。保留负责人参与设计的 `src/config/` 结构，评估已有新 pipeline 代码和旧开源代码，区分可迁移、仅参考和需要重写的部分。只为当前 PR 的实际用途创建文件，不预建空模块。

本 PR 不实现真实下载、真实 venue adapter、PostgreSQL 账本、完整隔离和人工审核系统、分钟聚合、回测引擎或 HTML 看板。历史覆盖、真实 API、恢复和吞吐量须在相应后续工作中验证。

## 工作流程

负责人于 2026-11-09 授权连续实施代码阅读清单，实施记录和设计选择供之后重新 review。Analyst 更新相关测试及文档；Reporter 报告用途、设计、实际检查和限制。Validator 独立审查，不替负责人决定合并。当前修复进度和各块待办以 [代码阅读进度](CODE_READING_PROGRESS.md) 为准。

2026-11-13 负责人授权实施本次阅读待办，并由 agent 决定常规问题。按依赖顺序使用以下审查块，每块经独立 Reviewer 循环，最终由独立 Validator 检查整个本次修复：

| 块 | 本次范围 | 可检查的验收例子 |
| --- | --- | --- |
| B5 | Bronze 来源、原始内容和明确的本机时间异常 | 非 venue / 无 API 版本可表示；有效 JSON 或原始字节能保存且不混淆；损坏字节保留证据；写入时间早于接收时间时不输出 Silver。 |
| B6 | Silver 市场、选项和结算字段 | 可保留市场描述、结算条件、计划与实际时间；选项说明可空，不同市场身份区分；未知结算时间不编造。 |
| B7 | 每日数据时间边界和后续质量限制的明确记录 | 当日数据的可用时间不能早于该 UTC 日开始；不假设日内汇总必须等到当天结束；其他质量问题按相应后续 PR 处理（记录于 [SCHEMA_REVIEW.md](SCHEMA_REVIEW.md) “关键选择”第 7 条）。 |

当前 PR 仅提供原始记录契约及 mock 边界，不实现真实采集、源文件导入、manifest 账本、持久化编排或人工审核；原始文件应按具体来源在后续相关 PR 选择保存方式和登记信息。B5 的原始字节字段用于可表示一条原始记录，不要求把大型文件装入一条内存记录；不能把测试中的内存保留声称为已落盘。

## 已知待验证

- Polymarket 的不同市场及 outcome 标识映射、两平台历史成交和盘口覆盖，以及实际协议精度。
- 数据版本与 manifest、文件和账本的一致性，异常恢复及人工审核的具体实现。
- 分市场、日期的 Parquet 文件数量及 dictionary 字段对真实规模回测和看板查询的影响。
- 完整检查和独立审查结果以最终工作区的实施记录为准；测试通过不证明生产环境的持久性或真实性能。
